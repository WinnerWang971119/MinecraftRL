# M4 Self-Play (issues #8, #9, #10) + iron loadout (#33) Plan

**Goal:** Drive the second bot in every arena with a frozen past-self policy, sampled by PFSP from a persisted snapshot pool, with Elo logged over training — so a self-play-trained, iron-equipped agent can fight human challengers on 2026-08-21.

**Approach:** Reuse the `opp_action` wire seam that already exists. `MCPvPEnv` gains a second `PerceptionFilter` and computes BOTH seats' observations **eagerly, exactly once per ingested state**, caching them; `opponent_observation()` returns the cache. A `SnapshotOpponentDriver` — built by the same lock-guarded memoized per-arena factory pattern as `build_scripted_opponents` — feeds that mirrored observation to a frozen `DuelingDRQN` and returns its greedy macro. Both fighters are equipped with an iron sword and full iron armor, which is a **regime migration**, not a cosmetic change.

Approach chosen at Phase 4 ("A: env-owned mirror"). Both independent consultants ENDORSED it and converged separately on the same refinement — compute eagerly and cache, never lazily inside the accessor.

## Decisions

- **Development happens in a git worktree** at `/Users/diego/Documents/MinecraftRL-m4`, branch `feat/m4-selfplay` off `fix/yaw-convention` — because the live run has `bridge_restart=on`, so checking the main tree out to another branch would have auto-restarted bridges silently come back running different code mid-run.
- **Run name is `m4_selfplay`.** The currently running bare-handed M3 retry already owns `runs/m4.pt` / `runs/m4.best.pt`, which is also this run's warm-start source. Reusing the name would overwrite the warm start with its own output.
- **Mirrored observation is computed eagerly and cached**, in lockstep with `_state_to_obs`. Non-negotiable: a lazily-computed accessor ages perception memory a variable number of times per window, which silently trains the learner against a broken opponent.
- **Mirror logic lives in a sibling module**, not inline in `MCPvPEnv`, to keep the frozen contract file's diff reviewable.
- **The opponent gets an iron sword, not just armor.** Discovered during planning: the datapack never arms the opponent and `dummyResetTemplate` is `inventory: []`. Armor without a weapon means ~0.4 HP per punch, ~50 hits to kill, nothing terminating inside 600 steps — every episode a draw, PFSP flat, Elo pinned at 0.5, the whole training window wasted.
- **Armor cannot be verified by the reset read-back gate.** `bot.inventory.items()` covers slots 9-44 (`prismarine-windows/index.js:11`); armor occupies 5-8. A separate live probe is required, because a `$`-macro abort would otherwise ack a reset that equipped nothing.
- **Elo rates immutable policy-version identities**, records opponent ID and epsilon per match, and only fixed-greedy matches are Elo-eligible.
- **The demo checkpoint is selected from snapshot FILES on disk**, by aggregate and worst-case performance against the three pinned references — never by peak Elo alone, and never from a net held by reference.
- **Snapshot 0 is the M3 warm start, permanently retained**, and is one of the three pinned references. Win-rate against it is the absolute-skill trend line that Elo alone cannot provide.
- **Frozen opponents act with a small epsilon (default 0.02)** so greedy-vs-greedy pairs cannot lock into deterministic loops. Draws (600-step timeout) score 0.5.
- Assumptions carried forward without a confirmation gate (auto mode): `gamma` stays 0.99 despite longer episodes — dense damage reward is unchanged in total and carries learning; if the canary shows the terminal signal is not propagating, raising `gamma` to 0.995 is the first lever.

## Data Model

```python
@dataclass(frozen=True)
class SnapshotRecord:
    snapshot_id: int          # immutable policy-version identity
    grad_step: int            # learner grad step at creation
    path: str                 # runs/<run>/snapshots/snap_<id>.pt
    elo: float                # frozen at creation = learner's Elo then
    pinned: bool              # snapshot 0 and the reference set are never evicted

@dataclass
class MatchStats:             # per snapshot, rolling
    plays: int
    learner_wins: float       # draws count 0.5
    def win_rate(self) -> float: ...

# Elo: E_a = 1/(1+10**((R_b-R_a)/400)); R_a += K*(S_a-E_a), K=24
# Only the LEARNER's rating moves. Snapshot ratings are frozen at creation.
```

Checkpoint payload for a snapshot mirrors the existing best-checkpoint shape:
`{"model", "grad_step", "code_version", "snapshot_id", "elo"}`.

## Error Handling

- **Snapshot file missing/corrupt at sample time:** log loudly, drop that snapshot from the pool, resample. Never fall back to an untrained net.
- **Pool empty:** impossible by construction (snapshot 0 seeded at startup from the warm start). If it happens, refuse to start.
- **Mirror requested but wire fields absent:** refuse at env construction with a message naming the four surfaces — do not silently substitute constants.
- **`opponent_observation()` before any state:** raise, matching `raw_opponent_view()`'s existing behavior.
- **Episode aborted mid-flight (`BridgeError`):** the match is not scored into Elo or PFSP stats, matching how the scripted curriculum already declines to score aborted episodes.
- **Armor probe fails:** refuse to launch the run. A silently unarmored fleet trains the wrong game.
- **`step()` reply loss:** unchanged — abort, never retry. `reset()` keeps its bounded reconnect.
